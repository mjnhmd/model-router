# Web 控制台设计

## 目标
给 model-router 加一个可视化控制台（单页），让用户：
1. 实时看所有上游模型的速度（tokens/s、延迟、健康状态、错误率）
2. 勾选/取消勾选要参与路由的模型（笨的、贵的、不想用的直接关掉）
3. 在自动择快路由池中勾选、筛选和管理模型，不需要编辑配置文件
4. 手动触发测速，并能看到测速状态
5. 查看请求日志和运行期统计

## 交互原则
- 面向「看板」而非「配置器」：一眼看清谁快谁慢、谁挂了
- 勾选即生效、实时刷新，不重启服务
- 禁用模型立即从路由候选剔除；卡很贵的模型不让选
- 默认排序把已勾选模型放前面；可切换名称、速度、价格排序
- 已选模型池默认折叠，仅用于展示顺序管理；实际请求始终按同协议健康模型的吞吐择快
- 批量操作收敛为一个三态“选择当前显示”勾选框，筛选后只作用于当前结果
- 日志不记录提示词和响应正文；统计只覆盖当前代理进程生命周期

## 架构
- 后端 FastAPI 提供：
  - `GET /v1/status`：模型列表 + 实时评分（tps/latency/healthy/enabled/pricing/priority）
  - `POST /v1/models/reorder`：保存模型池顺序
  - `POST /v1/bench`：手动触发一轮测速
  - `GET /v1/logs`：读取最近请求日志
  - `GET /v1/stats`：读取当前进程统计
  - `POST /v1/models/toggle-batch`：按稳定模型 key 批量切换 enabled
- 启停状态、模型池顺序和路由策略写回独立 state YAML
- App 内嵌 `web/index.html` + `web/console.js`，原生 JS，3 秒串行轮询 status，失败可回滚并提示重试
- 不引前端构建，不用 npm；静态文件由 FastAPI 挂载

## 技术决定
- 前端零依赖：原生 HTML/CSS/JS + fetch + 简单表格
- 状态模型：`Router.enabled` 集合（默认全开）
- 打分仍由既有 EWMA 负责，Web 只读展示 + enabled 控制

## 范围
- 服务使用稳定 `id`，名称只影响显示；模型池顺序不参与实际选路
- 不做鉴权（本地 127.0.0.1 服务）
